# Localization

The interface speaks 23 languages: English, Hebrew, Russian, Arabic, Spanish,
French, German, Portuguese, Italian, Dutch, Polish, Ukrainian, Czech, Romanian,
Swedish, Danish, Norwegian Bokmål, Finnish, Greek, Turkish, Japanese, Korean
and Simplified Chinese. Hebrew and Arabic turn the whole shell right-to-left.

## Which language you get

In this order:

1. the language the account chose (Settings → Account → Interface language),
   kept on the server so it follows the person to every device;
2. failing that, the browser's language list, matched against the supported
   set (`zh-*` is Simplified Chinese, `pt-*` Portuguese, `no`/`nn`/`nb`
   Bokmål);
3. failing that, English.

Switching is immediate - no reload - and sets the document's `lang` and
`dir`. The last choice is also remembered in the browser so a returning
reader does not see a flash of English before the session answers.

## What a book's direction has to do with it

Nothing. A Hebrew book reads right-to-left inside the reader whatever
language the interface is in, and an English book reads left-to-right in a
Hebrew interface: the reader takes the book's own direction (declared in the
EPUB, or inferred from its language) and scopes it to the page, while the
chrome around it follows the interface. Technical values - paths, URLs, codes,
keys - are isolated with `<bdi>` or `dir="ltr"` so they read the same way in
every direction.

## What is translated, and what is not

Everything a person sees in the app is translated: the shell and navigation,
sign-in, the first-run wizard, the library, shelves and browsing, the reader
and the player, the book page, pairing, people, notes, Reading Now, the
reading list, processing states, empty states, errors and confirmations,
accessibility labels, tooltips and status messages. Plurals go through each
language's own rules (`Intl.PluralRules`), and numbers, percentages, dates,
relative times ("3 minutes ago"), byte sizes, ordinals and language names are
formatted for the interface language with `Intl`. Durations shown as `m:ss`
keep ASCII digits everywhere: a scrubber timestamp is a number to be read at
a glance.

Not translated, on purpose:

- Diagnostic text the server writes for the operator and the client shows
  verbatim: background-job progress lines ("Probing …", "Aligned 1,204
  sentences"), preflight check details, indexing error messages, pairing
  evidence notes and alignment refusal reasons. They are technical, they go
  into logs and bug reports, and they read the same to the person who has to
  act on them.
- The product name.
- The PWA manifest (name, description), which the platform reads once at
  install time.

## Honesty about the translations

Every language other than English was generated by a language model and has
not been reviewed by native speakers. The app says so under the language
picker. They are checked mechanically - every key present, every argument
matched, every plural branch a category that language actually has - but not
for tone, register or idiom. Corrections are welcome: the catalog is plain
text.

## Where the strings live

`web/src/i18n/messages/en/*.ts` is the source, one fragment per surface,
merged into one flat map of `area.key` → message. `web/src/i18n/messages/
<locale>.ts` holds each translation as the same flat map. Messages use a
small subset of ICU MessageFormat (`{name}`, `{n, plural, …}`,
`{n, selectordinal, …}`, `{kind, select, …}`), implemented in
`web/src/i18n/format.ts` without a dependency. `web/src/i18n/catalog.test.ts`
fails the build if a language is missing a key, carries an extra one, uses
different arguments, or uses a plural category its rules cannot produce.

To fix a translation, edit the value in that language's file. To add a
string, add it to the English fragment for its surface and to every language,
then use it with `t('area.key', { …values })` from `useT()`.
